# Learning-curve batch plotter

Double-click **绘制学习曲线.cmd** in the experiment root, or **start.cmd** in this tool directory, to open the plotting window.

1. The experiment root defaults to the parent of this tool directory, namely `D:\experiment`.
2. Enter participant IDs such as `01`, `01,02,04`, or `01-05`. `1` is also recognized as `01`.
3. Click the button for plotting the entered IDs, or the button for plotting all participants.
4. Click the button for opening the output folder to view results.

There is no need to enter training condition or actual shot counts. The program identifies baseline, training, test, and both, strength, angle from filenames.

## Output

Results are saved in `learning_curves` under the experiment root:

- `01.png`: high-resolution, six-panel figure entirely in English.
- `01.svg`: scalable vector figure.
- `statistics/01.json`: actual shot counts, block results, pre/post means, and source-file verification information.
- `batch_report.json`: successes, failures, and data notices from the most recent batch.

Other participants are likewise named by ID. Repeated runs update figures with the same ID. Original CSVs are not modified.

## Data directories and naming

Nonempty `MOLT4_results_v3/csv/` takes priority; the following legacy layouts remain supported before v3 recomputation. Versions are not mixed:

```
<experiment_root>/01/MOLT4_results/csv/*.csv
<experiment_root>/01/MOLT4/_results/csv/*.csv
```

For example, `01_04_training_both_140shots.csv`. The `140shots` filename suffix is only a check; **statistics always use actual CSV rows**.

Legacy CSVs use `shot` and `value`. The new both format uses `shot`, `strength_value`, and `angle_value`, allowing the original `value` to be blank. Single-condition strength/angle files prefer the corresponding component column when present, otherwise falling back to legacy `value`.

The new format uses each component's own `strength_maximum` / `angle_maximum` for caps; compound `unit` strings such as `strength:origin_to_strip;angle:degree` are parsed separately. The program does not exclude records or add special markers based on `needs_review`.

Each participant should have one training file and one baseline/test file per both, strength, and angle condition. A missing stage is indicated on the figure. Multiple files for the same stage/condition cause an error to prevent ambiguous pooling. A failure for one participant does not stop plotting other participants in the batch.

## Six panels and statistical conventions

- a: trial-level performance and block means for the automatically detected training condition.
- b: sample standard deviation within training blocks.
- c: proportion at the recorded maximum within training blocks.
- d–f: baseline and test for both, strength, and angle respectively.

**New two-component both format:** when training=both, panels a, b, and c each stack strength and angle vertically. Regardless of training condition, panel d displays both components of both baseline/test. Each component has its own y-axis and units. Components of the same both file are not pooled with separate strength/angle-condition data and do not double the total trial count. Panels e and f continue to show the separate strength/angle conditions.

In the new figures, `n = scored/recorded` means scored observations / actual records. For example, `n = 9/10` means this component has 9 valid scores among the block's 10 shots.

By default, each 10 actual records form a consecutive, nonoverlapping block. Sort by shot and retain all record positions; gaps in shot numbering are not filled. The two both components share block boundaries and calculate means/SD using their available scores independently. Blank `unresolved` scores are not replaced with zero and do not remove a valid value in the other component. Final blocks shorter than 10 shots are still shown. With only 1 score, the mean is computed but SD is unavailable; a block with no scores has neither mean nor SD.

Missing component columns, mixed legacy/new baseline-test metric schemas within a condition, duplicate shot IDs, or invalid nonempty values cause errors to prevent mismatching. Legacy scalar both retains its original plotting behavior; two components are not inferred.

Baseline uses all actual records in that condition as the reference. Test is divided by actual records into blocks, showing each block's shot range and n. Conditions are not pooled. Each condition uses its own scale; distance measures retain original recorded units, and CSV unit degree is displayed as degrees.

Error bars show mean ± 1 sample SD, not confidence intervals. All records participate normally, with no special review markers or exclusion dashed lines. Cap detection allows CSV rounding error; a shot without maximum metadata is excluded from the cap-proportion denominator, and insufficient metadata is noted in the panel.

These are descriptive block curves with no significance tests. An immediate test with feedback can describe pre/post changes, possible transfer, and changes within test, but cannot alone establish long-term retention or causal effects.

English a–f captions remain below the figure; the full paragraph at the bottom of the demonstration figure has been removed.

## Optional command line

```
python learning_curves.py 01
python learning_curves.py 01 02 04
python learning_curves.py 01-05
python learning_curves.py --all
python learning_curves.py 04 --block-size 10
python learning_curves.py 01 --root D:\experiment --output D:\experiment\learning_curves
```

Everyday use does not require the command line. Plotting libraries for the current Windows Python 3.12 installation are stored in this tool's `.deps`, independent of the previous demonstration-figure directory. The launcher prefers this computer's Codex Python and tries system Python if unavailable. When moving experiment data, select the new root in the window. Another computer needs compatible Windows Python 3.12 with tkinter; copy the entire tool directory, not just start.cmd.

## 2026-10-20 naming compatibility

The UI, legends, and new files consistently use both. Legacy regular is a read alias only; simultaneous both/regular files for one stage are rejected as ambiguous. Missing invalid/unresolved components remain blank; the other valid component and original shot order are preserved. Renaming existing v1/v2 CSVs does not change original scores/versions. Renaming does not turn old figure angles into v3 angles. Only newly reanalyzed v3 exports use the 8 cm angle threshold, the new O→endpoint angle, and strength-priority validity for both.
